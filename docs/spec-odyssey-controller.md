# Samsung Odyssey（Windows Mixed Reality）モーションコントローラ 技術仕様

> 目的: 本コントローラのタッチパッド／スティックを「マウス代替」として使う独自入力ツールを実装するための下調べ。
> 本文書は実機（右コントローラ）からのライブ計測に基づく。

計測ログ:
- `logs/hid-caps-1.txt` … リンクコレクション構造 + Input/Output/Feature の caps ダンプ
- `logs/hid-capture-1.txt` … 150 秒統計（値域・変化回数）
- `logs/hid-buttons-2.txt` / `logs/hid-buttons-3.txt` … 押下イベント（時刻・押下回数）

### Windows から見た扱い
- `C:\Windows\INF\input.inf` の `HID_Raw_Inst` が適用される **Raw HID デバイス**。
  → XInput / DirectInput（旧 joy.cpl）にはゲームパッドとして現れない。
- WMR ランタイム無効（`MixedRealityPortal.exe` 無し、OpenXR は Meta Horizon）。
  → OpenXR 経由でもコントローラ入力は取得できない。
- したがって入力を取るには **Raw HID / Raw Input で直接扱う** しかない（後述 §9）。

### 3-1. タッチパッド（idx10/11）の実測挙動【2026-10 確定】

生ログ（`logs/pad-drag.csv`, `logs/pad-snap.csv`, `logs/pad-v3.csv`）から確定した事実:

| 状態 | 報告値 |
|---|---|
| 指が触れている | 指の絶対位置（各軸 0..100 程度、整数・粗い量子化。速い動きでは 1フレームに 10 単位以上動くこともある） |
| 指を離している | **(a) 255,255 を返す** か、**(b) その時点の「休止値」を返し続ける**。両方あり得る |
| 休止値の例 | (49,50) / (50,51) / (50,53) / (56,65) / (57,64) / (58,63)。**1つに固定ではなく、セッション中に緩やかにドリフトする**。同一値が最長 22 秒連続で報告された例を確認 |
| 接触ビット idx6 | pad-v4 では指を離しても 1 のまま。**pad-v5 では 255 と同時に 0** になった（状態依存で信頼できない） |

**指を離したときの値は一定ではない【2026-10 pad-v5 で追加判明】**
- 離すと 255,255 を返すモードがある（このとき idx6 も 0）。1 回のログで 255 が 29980 フレーム中
  19277（64%）、ラン長は最小 9 フレームで「ドラッグ中のちらつき」は無かった。
- **指を置いたまま静止していると「実値2フレーム + 255 が約200ms」を繰り返す**ことがある
  （実測 t=146.7〜148.4: 97,71 → 255×40フレーム → 97,73 → 255…）。
  → 255 は「未接触」だけでなく「新しいサンプルが無い」も意味する。
- ただし**動かしている間は実値が連続して出る**ので、移動そのものは失われない。
- 静止中の 255 を即リフトと見なすと偽セッションが生じ得る。短い接触（移動12単位以下・0.25秒未満）は
  45 回あったが、`TapMinSec=0.04` により **0.04 秒以上続いた 9 回だけ**がクリックになり、
  誤クリックの報告は無かった（255 は最短 9 フレーム＝45ms なので、静止中の偽接触は閾値未満になりやすい）。

→ **「未接触＝固定のニュートラル値」という前提は成立しない。** 1 つの基準点を学習して距離で判定する方式は誤判定する（実測: 学習値 (57,64) に対し別のホーム値 (50,51) が出現し、13 単位＝31px の逆方向ジャンプを誘発した）。

**また、指を置く/離す瞬間に 6〜31 単位の瞬間ジャンプが必ず出る。**

このジャンプをそのまま差分としてカーソルへ流すと毎回 14〜74px が逆方向に注入され、**「カーソルがゴムのように元の位置へ引っ張られ、自由に動かない」** 現象になる（実測: 180 秒で 42 回、平均 20.2 単位＝48px の逆走）。

対策（PoC 実装済み）:
1. **タッチダウン** = 値が 50ms 以上まったく変化せず（＝無接触）、そこから 3 単位以上動いた
2. **リフト候補** = 接触中に値が休止値の 4 単位以内へ戻った（または 30 単位以上のジャンプ）
   → 候補の段階では確定せず、**次フレームで「休止値に留まっているか」を確認**してから確定する。
     休止値を横切っただけの本物の移動を捨ててしまうのを防ぐため。
3. 255,255 の出現 = 即リフト
4. **休止値の追従は「接触セッションが開いていないとき」に限る**。セッション中に追従すると、
   指を止めた位置を休止値と誤認し、離したときの戻りを検出できなくなる。

さらに **位置フィルタ（`-PadSmoothTau`）は毎フレーム更新する**。この実機は指を止めると生値を
完全に凍結して返すため、「変化したフレームだけ更新」だとフィルタが古い位置を抱えたまま停止し
（実測: 生値 49 に対しフィルタが 33.87 のまま **300ms 以上**滞留）、次に動かした瞬間に
**古い方向の移動がまとめて噴き出す**。これがゴム感の主要因だった（実測 t=58.8〜59.2）。

旧方式（フィルタ凍結＋即時リフト判定）と新方式を**同じ実測ログ（`logs/pad-v4.csv`, 操作は82秒）**で
再生した比較（`tools/simulate-v5.ps1`）:

| 同じログでの比較 | 旧 | 新 |
|---|---|---|
| 偽リフト（本物の移動を捨てた回数） | 9 回 / 165 単位 | 3 回 / **0 単位** |
| 逆走フレーム | 15 | **3** |

さらに、修正版を実機で動かした 150 秒ぶんのログ（`logs/pad-v5.csv`, 接触セッション189回）と
旧実装のログ（`logs/pad-v4.csv`, 操作82秒, 接触セッション31回）の実測比較:

| 実測 | 旧実装 (pad-v4) | 新実装 (pad-v5) |
|---|---|---|
| カーソル総移動量 | 22227px | 68705px |
| 逆走フレーム / 合計 | 172 / 379px | **9 / 19px** |
| 逆走（カーソル移動 1000px あたり） | 7.7 フレーム | **0.13 フレーム** |
| タップ | 1（偽リフト由来の誤クリック） | **9（意図したタップ）** |

ユーザーの体感でも「ゴム感は消えた」「タップは狙った通り」「追従は良くなった」を確認済み。

> 差分そのものは「指ではあり得ない大きさ（1フレーム≒5ms に 6 単位超）」という単純なしきい値では分離**できない**。実測で jump 8〜13 のスナップは 8 割が本物の指の動きだった。休止値の前後関係（凍結しているか）でのみ分離できる。

### 3-2. IMU（加速度・ジャイロ）・コンパスの識別【2026-10-19 動作試験で確定】

vendor ページ（0xFE）に並ぶ 24bit×6・16bit×3 のどれが何かを、`tools/hid-monitor.ps1 -Sensor` による
120 秒・387 サンプルの動作試験（静止 → 待機 → 持ち上げて回転／振り → 静止）で確定した。

| idx | 決定した意味 | 静止時 | 操作時 | 判定根拠 |
|---:|---|---|---|---|
| 13/14/15 | **加速度 X/Y/Z**（24bit 符号） | `\|a\|` ≒ 496,000 の一定ベクトル | 最大 1,910,542 | 静止は重力だけなので大きさが一定。振りでは約 3.9g まで増え、線形加速度に反応する |
| 17/18/19 | **ジャイロ X/Y/Z**（24bit 符号） | 0±1,600〜3,700 のノイズ | 最大 3,134,406 | 静止でほぼゼロ、回転すると静止値の 1000 倍超＝角速度センサ |
| 21/22/23 | **コンパス（地磁気）X/Y/Z**（16bit 符号） | `\|m\|` ≒ 430〜650 | 姿勢変更で 1,000 台へ | 振り・回転の瞬間には跳ねず、向きを変えたときに静かに別の値へ移動する |
| 16 | **温度** | 36.5℃ 前後 | 36.9℃ まで上昇 | 0.01℃ 単位。動作で僅かにあがる |
| 20 | **タイムスタンプ** | +10,033,337/秒 | 同 | 100ns 単位で実時間と一致 |
| 24 | **センサ状態** | — | 0 / 1 / 3 | IMU（acc/gyro）が 0 になっている区間では**必ず 0** |

読み方（生値・**未較正**）:

- 1g ≒ 49 万カウント（24bit 満量程なら約 ±17g 相当）。**中心（オフセット）は静止時から毎回推定する**必要がある。
- ジャイロのスケールは未確認。±2000°/s 想定なら 1LSB ≒ 4,194 カウント/(°/s) で、静止ノイズ 1°/s 未満・
  実回転 約 750°/s と整合する。
- コンパスは未較正（ハードアイアン等の補正なし）。姿勢を変えない限り値が変わらない。
- 軸の順番・正負は未検証（0x453/454/455 = X/Y/Z の順と推定）。

**注意: コントローラがスリープすると加速度・ジャイロは 0 が明示的に報告される**（コンパスは生きている）。
このとき状態フラグ（idx24）も 0 になるので、起床状態の判定にはこれを使う。実測 120 秒のうち 105 サンプルが
この IMU=0 区間だった（持ち上げると復帰する）。

観測方法:

```
powershell -ExecutionPolicy Bypass -File tools\hid-monitor.ps1 -Seconds 60 -Sensor
powershell -ExecutionPolicy Bypass -File tools\hid-monitor.ps1 -Seconds 120 -Sensor -LogFile out.txt
```

300ms 毎に `加速度=(x,y,z) |acc|=…  ジャイロ=…  コンパス=…  温度=…  ts=…  状態=…` を 1 行出し、
終了時に 3 系の大きさの min/max 集計を出す。マウス用途では引き続き未使用（入力は idx7〜11 のみ参照）。

**ビジュアライザ `tools/sensor-viewer/`**（2026-10 追加）: GDI+ で描くセンサ確認ツール。
画面は **左＝大型の姿勢キューブ**（ジャイロ積分＋加速度による重力補正＋コンパスによる
yaw 補正の相補フィルタ）／ **右＝数値パネル＋グラフ 3 枚**（加速度・ジャイロ・コンパス）。
コントローラを傾ける・回すとキューブが一緒に動く。読み取りは本体アプリと同じ経路なので
`OdysseyMouse.exe` と同時に動かせる。

```
powershell -ExecutionPolicy Bypass -File tools\sensor-viewer\build.ps1     # csc のみでビルド
tools\sensor-viewer\dist\SensorViewer.exe                                  # UI 起動
tools\sensor-viewer\dist\SensorViewer.exe -SelfTest 10                     # 画面なしの回帰確認
```

UI キー: `Space` 一時停止 / `B` ジャイロ基準化 / `W` 表示窓 (2/5/10 秒) / `S` CSV 保存 /
`R` 姿勢リセット / 矢印・`,` `.` 見立てオフセット / `[` `]` ジャイロ感度 /
`M` コンパス yaw 補正 ON/OFF / `N` 方位基準リセット / `Esc` 終了。

方位コマ（キューブ右下）は 2 本の針: 黄＝世界座標の磁気方位（補正中は固定＝北の目印）、
水色＝コントローラの前向き（体 +X）。両者の開きが「起動後に回った角度」。

`-SelfTest` は実機データの統計に加えて**合成データで姿勢フィルタも検証**する
（A 静止で 0deg / B 90deg/s×1秒で 89.5deg / C 重力補正の収束 / D 振り中は補正しない /
E マグ yaw 補正でドリフト 30.1deg → 2.1deg → `orient filter = OK`）。

既知の制約:

- **yaw（水平回り）は地磁気で補正する（既定 ON）が、地磁気は未較正**（ハードアイアン等、
  コントローラ内に磁性体あり）。傾きを変えると方位誤差が出るので、ずれたときは `N` で
  方位基準を取り直すか `M` で補正を切る（切ると yaw はドリフトする）。
- ジャイロのスケールは **±2000deg/s 想定（1LSB = 4194 counts/(deg/s)）** の推定値。実物が違うと回転速度が比例してずれる
  → `[` `]` キーで表示倍率を調整して合わせる。
- キューブの軸は**センサ軸基準**（0x453/454/455 = X/Y/Z と推定）。本体の向きと合えば矢印キーの見立てオフセットで揃えられる。
- IMU がスリープしている間は積分を止め、明けの巨大な dt は捨てる（姿勢が一瞬で飛ぶのを防ぐ）。
- グラフは TableLayoutPanel のセルに置くため **Anchor を全方向に固定しないとサイズ 0 のまま描画されない**
  （位置は合わせてくれるが引き伸ばしはしない）。実装は `MakeChart` で設定している。

## 4. ボタン（DataIndex 0〜6 / 7個）

`HidP_GetData` は **押されているボタンだけ** を返す（未押下は列挙されない）。
また `HidP_GetButtonCaps` の内容は本デバイスでは不正（BitSize=0, usage重複）で、**用途名は caps からは信頼できない**。
→ そこで「1 操作ずつ・押下イベントを時刻順＆回数で観測」して対応を確定した（`logs/hid-buttons-2.txt`, `logs/hid-buttons-3.txt`）。

| DataIndex | 物理入力 | 根拠（第3回計測） |
|---:|---|---|
| idx9（アナログ値） | **トリガー**（引き込み量） | 0→36→174→255→0。**全引きしてもデジタルボタンは発生しない**＝トリガーはアナログのみ |
| 0 | **グリップ** | 押下 1 番目（独立に 2 回観測） |
| 1 | **メニュー** | 押下 2 番目 |
| 2 | **Windows** | 押下 3 番目 |
| 3 | **スティック押し込み** | 押下 4 番目 |
| 6 | **タッチパッド接触** | 「触れるだけ」で発生。座標 idx10/11 の 255→値 と完全同期（クリック無しでも発生）。**ただし後の長時間計測では指を離していても 1 のままで、接触判定には使えなかった**（§3-1 参照） |
| 4 | **タッチパッドクリック** | 「カチッと押す」で発生（idx6 と同時だが、⑥⑦の分離により独立と確定） |
| 5 | **未使用** | 全 3 回の計測で押下 0 回。トリガーはアナログのみなので、物理入力に対応しない空きスロットと判断 |

> 宣言上は 7 ボタン（DataIndex 0..6）だが、**実使用は 6 個**（0,1,2,3,4,6）。デジタル入力は「グリップ／メニュー／Windows／スティック押込／タッチパッド接触／タッチパッドクリック」の 6 種で、トリガーのみアナログ。

## 5. 出力（ハプティクス / 振動）

- 出力 ReportID **4**、リンクコレクション node3（`Haptics/0x00`）に：
  - `Haptics/0x23`（8bit, 0..100）
  - `Haptics/0x21`（8bit, 0..100）
- 2 チャンネル（左右 or 強弱）の振動モーター。値 0..100 で強度指定。

> **送信方法の注意（Bluetooth HID）**: `HidD_SetOutputReport` は本デバイスでは `ERROR_NOT_SUPPORTED (50)` になる。
> またハンドルを **書き込みアクセス付き**（`GENERIC_READ|GENERIC_WRITE`）で開く必要がある。
> 実際に動くのは **`WriteFile(handle, [ReportID=4, chA, chB], len)`**（len は 64B でも ID+2 の 3B でも成功）。
> → 出力レポートは `WriteFile` で送る。

> **⚠ 入力ストリームが停止する現象について（実測で原因確定）**
>
> セッション中に入力 ReportID 1 の受信が止まり、`ReadFile` が
> `err=258 (WAIT_TIMEOUT)` → `err=1167 (ERROR_DEVICE_NOT_CONNECTED)` を返す現象が起きる。
> 当初は振動送信が原因と疑ったが、**振動を完全に無効化した状態でも発生**したため否定された。
>
> 真因は **コントローラ自身が Windows から切断されること**。Windows のイベントログに
> `HidBth` ID 2「Bluetooth HID デバイスは圏外になったか利用できなくなりました」が
> **切断時刻と完全に一致**して記録される（実測: 47 分間に 13 回）。
> ツール非実行中にも記録されるため、**デバイス側（低電池・省電力スリープ・Bluetooth 干渉）の要因**。
> ノート PC の Bluetooth と据置型 Bluetooth の両方で同じ挙動が見られる。
>
> **対策（実装済み）**:
> 1. 読み取りを**タイムアウト付きオーバーラップ I/O** にし、停止してもプロセスが固まらないようにする。
> 2. 連続失敗（4 回≒1 秒）を検出したら、**1 秒ごとにデバイスを再探索して自動再接続**する。
>    `HidBth` の切断は自然復帰するため、復帰を検知すると操作を継続できる。
> 3. 頻発する場合はコントローラの電池（単 4×2）を新品に交換する。

> **振動の既定OFFについて**: 上記の切断とは別に、振動を有効にした状態で
> 切断頻度が増える可能性は否定できないため、既定は OFF としている。
> `-HapticsStrength 60` で有効化でき、`-TestHaptics` で振動のみ単体テストできる。

## 9. 次段階: マウスマッパー実装方針（案）

1. **移動**
   - スティック（idx7/8）: 中心 2048・不感帯 ±N → 相対移動量（`MOUSEEVENTF_MOVE`）に変換。ベジェ/加速カーブ＋慣性で滑らかに。
   - タッチパッド（idx10/11）: 接触中（!=255）はパッド座標を **絶対位置** にマップ、または差分で相対移動。指を離したら停止。
2. **クリック**
   - タッチパッドクリック（idx4）→ 左クリック。
   - グリップ（idx0）やメニュー（idx1）→ 右クリック／中クリック。
   - アナログトリガー（idx9）→ 閾値超えで左ドラッグ等（オプション）。
3. **スクロール**
   - タッチパッド端の縦スワイプ、または Windows ボタン（idx2）併用でホイール。
4. **モード切替**（メニュー＋Windows 同時押し等）でカーソル/スクロールモードを切替。
5. **ハプティクス**（出力 RID4）… `WriteFile` で送信可能（`-TestHaptics` で確認済み）。ただし既定 OFF（§5 参照）。

実装言語は C#(WinForms/WPF) か C++ を想定（`SendInput` と Raw Input / ReadFile の常駐ループが必要）。PoC は本リポジトリの PowerShell スクリプト群で検証済み。

## 10. PoC 実装

`tools/odyssey-mouse.ps1` … 上記方針の動作する PoC（PowerShell + Add-Type）。

- 入力: HID `045E:065D` を **タイムアウト付きオーバーラップ `ReadFile`** で直読みし `HidP_GetData` でデコード
- 出力: `SendInput` でマウス注入（`MOUSEEVENTF_MOVE` 相対移動＋クリック/ホイール）
- 起動時にスティック中心を自動較正（実機の静止値は 2048 からずれ、X≈2000 / Y≈2270 程度で個体・その時々により変動）
- 既定の割当: スティック/タッチパッド=移動、タッチパッド押込(idx4)・トリガー(idx9)=左、グリップ(idx0)=右、スティック押込(idx3)=中、メニュー(idx1)=スクロールモード切替、Windows(idx2)=速度ブースト
- `-DryRun` でカーソルを動かさず値のみ確認可能。`-Trace` で毎秒のハートビート（レート/読取失敗/送信結果）を表示
- 主な調整パラメータ: `-StickSensPx`, `-StickDeadzone`, `-StickExponent`, `-PadGain`, `-WheelRate`, `-TriggerThreshold`, `-BoostFactor`, `-InvertY`
- タッチパッド: 速度依存の加速（`-PadAccelMax`/`-PadAccelRef`、速度 EMA の時定数 `-PadAccelTau` 既定 40ms）＋**毎フレーム更新の時定数ベース位置フィルタ**（`-PadSmoothTau` 既定 4ms、`1-exp(-dt/τ)`。レートが 20〜200Hz で変わるため固定係数は不可）。サブピクセルは `$accX/$accY` で繰り越すため、残量フォロワ（`-PadFollowTau`）は既定 0（＝使用しない）
- **機器側スナップ除去**（§3-1）: `-PadJumpMax`(既定 6) `-PadSnapEnd`(既定 30) `-PadRestBand`(既定 4) `-PadSmoothTau`(既定 0.004) `-PadFollowTau`(既定 0) `-PadAccelTau`(既定 0.04)。タッチダウン/リフト確定/255 のフレームだけ差分を捨ててアンカーを張り直す。リフトは 1 フレーム遅れて確認する
- **休止値は「取得できたときだけ」使う**。未接触時に 255 を返す実機では起動時に休止値を学習できないため、その場合は休止値条件を無効化し、255 と瞬間ジャンプだけで判定する（学習できた場合は `PadRestBand` 条件と、巨大ジャンプ後に値が止まったかどうかの両方でリフトを確認する）。
- タッチパッドの**タップ**で左クリック（`-TapMaxSec`/`-TapMinSec`/`-TapMaxMove`, `-NoTapClick` で無効）。判定は「タッチダウン位置からの距離」で行い、**タッチダウンが検出できたセッションだけ**を対象にする（休止値の上で始まった偽セッションを除外して誤クリックを防ぐ）
- 振動フィードバック（`-HapticsStrength`/`-HapticsMs`）は**既定 OFF**（§5 参照）。`-TestHaptics` で振動の単体テストのみ可能
- **切断の自動復帰**: 読み取りが連続失敗すると切断と判定し、1 秒ごとにデバイスを再探索して自動で開き直す（§5 参照）

> 実測レート: 操作中/アイドルとも概ね 200 Hz（60 秒で約 12,000 レポート）。
> **ハードウェア上の限界**: タッチパッドの分解能は約 0..100（101 段階）で、
> ノート PC のタッチパッド（1000 段階以上）に比べ原理的に粗い。平滑化で見た目は改善するが上限がある。
> 精密操作は 12bit 分解能のスティックが有利。

### 11-7. 実機で直した 2 点（2026-10-19）

**(1) タップでカーソルがずれる問題**

- **接触開始で位置フィルタを再アンカーする**。`_padFX/_padPXf` は前回タッチした場所のまま
  次のタッチまで残るため、次に指を置いた瞬間にその差分が丸ごと移動として出ていた
  （最大 100 単位 ≒ 240px）。実接触の初フレームで今の値に合わせ、接触中は 255 のフレッタが
  あっても再アンカーしない（解除は確認済みリフトのみ）。
- **タップ確定時に着地後の移動を打ち消してからクリックする**。接触開始時点の出力累計を
  スナップショットし（`_padSnapX/_padSnapY`）、タップ成立時にその分を相対移動で戻す
  （`UndoPadOutputSinceTap`）。クリックは位置の戻しが先に SendInput されるよう、移動送信の
  後ろへ回している（`_pendingTapClick`）。ドラッグとして判定された場合は一切触らない。

**(2) ゆっくり動かしたときの「刻み」**

- 実測: タッチパッドの生値は **0..100（101 段階）**、更新は約 200Hz（X が変化する間隔の
  p50=5ms）。1 単位 ≒ 2.4px なので、低速時は 10〜30ms おきに 2.4px の階段が見える。
- 既定の平滑時間 4ms では階段を引き伸ばしきれない。逆に大きくすると高速時に遅延（ゴム感）が
  出るため、**速度依存にした**: 低速ほど平滑時間を長くし、高速では既定値へ戻す。
  `tau = PadSmoothSlowTau + (PadSmoothTau − PadSmoothSlowTau) × min(1, v / PadSmoothRef)`
  - `PadSmoothSlowTau` 既定 0.030 秒（UI「低速時のなめらかさ」、0 で無効）
  - `PadSmoothRef` 既定 150（パッド単位/秒、切り替え速度。INI でのみ変更可）
  - `PadSmoothTau` 既定 0.004 秒（既存、速いとき）
- プリセット: 精密 0.045 / 標準 0.030 / 速い 0.020

**(3) スクロールモードの上下方向**

- 修正前はスティックを上へ倒すと**下**へスクロールしていた。`ay` は `InvertY` 適用後の値で
  「上＝負」、Windows のホイールは「正＝上」なのに加算していたため。
- 修正後: `_wheelAcc -= ay * WheelRate * dt`。**カーソルの上下と同じ向き**に揃った
  （`InvertY` を変えても常にカーソルと連動）。左右は `hwheelAcc += ax * ...` のまま
  （右＝右スクロールで自然）。
- PoC `tools/odyssey-mouse.ps1` も同じ修正を入れて揃えた。

**(4) タブ／セグメント切り替えが二度目に効かない（UI の排他表示バグ）**

- 症状: タブを1回クリックすると切り替わるが、2回目以降のクリックが効かなくなる。
  実機で報告された。
- 原因: `Ui.cs` の `Segmented`（タブ・言語切替・プリセットの3か所で使用）が
  **RadioButton 1つごとに `Guid.NewGuid()` の GroupName を割り当てていた**。
  これで全ボタンが独立グループになり排他にならず、
  一度選んだタブは `IsChecked=true` のまま固化する。押しても `Checked` が出ず
  `SelectTab()` が呼ばれないので中身が切り替わらない（見た目も複数タブが選択状態になる）。
- 修正: GroupName を **`Segmented` インスタンス単位で1つだけ**発行
  （`var group = "seg" + Guid...` をループ外へ）。タブ／言語／プリセットは
  それぞれ別グループなので互いに干渉しない。
- 回帰確認（UIA + SendInput の実クリック）:
  - 4タブを2巡（計8回）連打 → 常に**選択は1つだけ**・中身も毎回一致。
  - 言語切替 `日本語 → English → 日本語` → 排他OK・タブ名も両言語で再表示。
